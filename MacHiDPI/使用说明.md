# MacHiDPI：M1 Pro 外接屏开启 HiDPI

本工具自行生成显示器缩放配置，通过 macOS 显示接口重新连接外屏并选择 HiDPI。无需 BetterDisplay 或 one-key-hidpi，无常驻进程，无启动项，无需关闭 SIP。

目标效果：例如原生 3440×1440 的外屏，桌面仍为 3440×1440，内部以 6880×2880 渲染，再缩回面板输出。物理 PPI 不变。

本机 Dell 两个档位、Duo 双屏原生桌面档位的拔插保持验证通过，详细尺寸和过程见 [验证记录](验证记录.md)。Duo 实测使用专用执行程序；本次正式版已整合双屏流程，完成构建和离线检查，未重新安装或切屏实测。睡眠、重启及其他档位的保持未验证。

## 选择字号与桌面空间：11 档 HiDPI

2026-11-03 新版将配置收敛为 11 个桌面候选档位。对本机 Dell P3424WE，桌面尺寸如下；每档目标均为 2× 渲染，表中放大幅度相对 3440×1440 桌面估算。

| HiDPI 桌面尺寸 | 界面放大约 |
| --- | --- |
| 3440×1440 | 0% |
| 3268×1368 | 5% |
| 3096×1296 | 11% |
| 2924×1224 | 18% |
| 2752×1152 | 25% |
| 2580×1080 | 33% |
| 2408×1008 | 43% |
| 2236×936 | 54% |
| 2064×864 | 67% |
| 1892×792 | 82% |
| 1720×720 | 100% |

全部保持本机原生宽高比。可先试中间几档，再按日常观感选择。本机已识别全部 11 档；未逐档评价画面或舒适度，具体核验结果见验证记录。其他屏幕仍按各自原生尺寸的 100%–50%、间隔 5% 取整生成，存在像素取整误差。

需要这组档位时，使用下述“安装配置”入口，不能只运行“直接开启”。安装后打开 **系统设置 → 显示器**，选择 Dell 外屏；按需展开“显示所有分辨率”，从系统识别出的 HiDPI 档位中选择。配置不会删除系统原有的普通分辨率，实际列表与可用性以安装后核验为准；无法保证界面只显示这 11 档。保留普通模式可供恢复。

“直接开启”“安装并开启”“重新连接并开启”默认切到检测到的原生桌面尺寸 HiDPI（本机为 3440×1440）；之后自行选择较小桌面。以桌面 2752×1152 为例，实际渲染应为 5504×2304；检查状态中的“当前 2× HiDPI：已启用”表示成功，“原生尺寸目标：未达到”仅表示选择了较小桌面。

已完成的安装、恢复和拔插测试汇总在验证记录中，不代表当前显示状态。

## Duo 双屏及现有高分辨率档位

2026-11-04 实测的 Duo 为两块 MB14FCD，各原生 1920×1200、60 Hz。两块屏共用一个型号配置文件；安装和恢复会逐块处理当前连接的同型号屏幕，并保存各屏安装前模式。同型号但原生尺寸不同的屏幕会被拒绝。

需要为现有普通分辨率中**宽度大于 1024、且宽高不超过面板原生尺寸**的每一档生成 HiDPI 时，在 MacHiDPI 文件夹运行：

```sh
./MacHiDPI list
./MacHiDPI plan --display 2 --all-resolutions
./MacHiDPI install --display 2 --all-resolutions
```

`2` 只是示例，须替换为 list 当前返回的 Duo 屏幕 ID；两块同型号屏选择其中一块即可。先审阅 plan。install 会提示影响的屏幕数，确认并完成管理员授权后逐屏重连、切至原生桌面尺寸 HiDPI。ID 在重新连接后可能变化。

本机这组选项生成 10 档：1920×1200、1920×1080、1600×1200、1600×1000、1344×1008、1344×840、1280×1024、1280×960、1280×800、1280×720。保留各档原有比例，不把 4:3、16:9 改为面板的 16:10；原有普通模式仍可能保留。其他显示器按当时系统提供的普通模式筛选，并非固定这 10 档。实际可用性须安装后核验。

不加 `--all-resolutions` 仍生成前述 11 档。此选项仅用于 plan、install、export；不会自动切换或逐档测试。enable、persist、reconnect 仅处理选中的一块屏；install、restore 处理该型号当前连接的全部屏幕。需要恢复时仍用正式工具 restore，并选择该型号任一当前 ID。

## 第一次使用：先直接开启

1. 保留整个 MacHiDPI 文件夹，不要只拿走 `.command` 文件。
2. 接好显示器，先退出其他显示器配置软件。
3. 双击 **直接开启HiDPI.command**，阅读提示，输入大写 `YES`。多台受支持外屏时按提示选择序号。
4. 看到“当前 2× HiDPI：已启用”和“原生尺寸目标：已达到”即成功。例如桌面 3440×1440、实际渲染 6880×2880。

这个入口只切换显示模式，不安装系统文件，不设置 DisplayResolutionEnabled，也不需要管理员密码。本机已在覆盖文件及该开关都不存在的状态下，验证普通模式 → HiDPI 成功。这不代表所有 M1 Pro 外屏都已预置目标底层模式。

双击 **检查状态.command** 可只读检查。较小桌面尺寸也可处于 HiDPI；状态把“当前 2× HiDPI”和“原生尺寸目标”分开报告。

## 需要整组缩放档位或找不到目标模式时：安装配置

1. 打开 MacBook 内屏，保留画面可操作。
2. 双击 **安装并开启.command**。
3. 阅读修改说明，输入大写 `YES`。有多台外接屏时，先选择序号。
4. 在 macOS 密码框输入管理员密码。程序自行生成并安装对应型号的缩放配置。
5. 外屏短暂黑屏、自动重连，再切换到 HiDPI；窗口可能移到内屏。无需手动拔插或重启。
6. 看到成功及目标渲染尺寸核验通过即完成。失败时使用下述恢复入口。

## 日常使用

需要保存当前选好的 HiDPI 档位时，在本目录运行 `./MacHiDPI persist`，阅读提示并输入 `YES`。它保留当前桌面尺寸和刷新率，向 macOS 请求永久保存，并核验返回值和当前实际像素；当前不是 2× HiDPI 时拒绝保存。可能短暂黑屏，系统会更新显示偏好；不安装显示覆盖文件或启动项。原有“直接开启”“安装并开启”“重新连接并开启”仍按会话范围切换，不会自动调用永久保存。

本机换档后未再次保存也通过了一次拔插检查，因此不要求每次换档后重新保存；其他档位尚未逐个验证。可用“检查状态”确认当前 2× HiDPI；验证拔插时先不要重新开启，以免掩盖实际保持结果。

macOS 可能把不支持的永久保存请求降为会话范围；提交成功不能代替拔插实测，也不保证睡眠或重启保持。

重新连接或重启后若回到普通模式，打开内屏，双击 **重新连接并开启.command**，阅读提示并输入 `YES`。此入口不重装配置，通常不需要管理员密码。

也可先重新运行免安装的 **直接开启HiDPI.command**。模式选择按当前登录会话生效。工具不自动在开机、唤醒时运行，睡眠唤醒及重启后的自动保持不作保证。

## 恢复

只有运行过“安装并开启”才需要恢复配置。若只运行“直接开启”，未安装系统文件，想退出 HiDPI 可在系统显示设置中选择普通模式。

打开内屏，双击 **恢复原配置.command**，选择需要恢复的型号，输入 `YES` 并完成管理员授权。工具还原首次安装前的覆盖文件，逐屏重连并尝试恢复保存的各屏分辨率。仍有其他型号由本工具管理时，保留 DisplayResolutionEnabled=true；最后一个型号恢复时才还原本轮共享管理开始前的开关值。

“安装前”指首次使用本工具时，不等于 macOS 出厂状态。如果安装前已经存在 BetterDisplay 或其他工具生成的配置，恢复也会保留那份原配置。

若运行过 persist，restore 仍只恢复原覆盖文件、开关和会话模式，不完整回滚永久显示偏好或历史。需要撤回永久保存时，在系统显示设置重新选择需要的模式；系统偏好没有字节级备份。

恢复后保留 state.json（managed=false）、原文件备份（如有）、临时文件和新建的空目录。再次安装继续复用型号文件的首次备份；确认当前文件已恢复后，会重新记录本轮连接的各屏模式，并采用本轮共享开关基准。因此旧单屏记录完成恢复后可重新安装为双屏。WindowServer 的显示历史也可能自行变化，恢复不等于所有文件和缓存逐字节回到原状。

若文件、共享开关基准或屏幕身份不能核对，工具停止自动覆盖或恢复，保留错误信息供检查。同型号屏幕可能报告重复的系统 UUID；原显示器 ID 仍在时可以逐屏处理，若 ID 改变且 UUID 也无法唯一匹配，停止而不猜测。旧版只保存单屏模式的记录，须只连接一块该型号屏幕完成恢复后再安装双屏配置。安装失败后也可使用恢复入口，不要手工清空整个 Displays 或 Preferences 目录。

若外屏未恢复，内屏保持可用；可拔插外屏连接线，然后运行检查状态。管理员授权取消时，不继续软件重连，但可能已留下恢复记录；可再次安装，或使用恢复入口处理这份记录。

## 会修改哪些文件

系统设置：

- 一个型号级显示覆盖文件：`/Library/Displays/Contents/Resources/Overrides/DisplayVendorID-<厂商十六进制>/DisplayProductID-<产品十六进制>`。目录缺失时创建。同型号的所有屏幕共用该文件。
- `/Library/Preferences/com.apple.windowserver.plist` 中的 `DisplayResolutionEnabled`。已为 true 时不写；否则设为 true。多个受管理型号继承同一个恢复基准，最后一个恢复时才还原。已恢复型号重新安装时采用当轮共享开关基准；型号文件的首次备份继续保留。其他键保持原样。

用户恢复记录：

- `~/Library/Application Support/MacHiDPI/<厂商>-<产品>/state.json`。
- 如果安装前有覆盖文件，同目录保存 `original.plist`。

管理员执行的临时文件位于 `/private/tmp/MacHiDPI-<随机编号>/`。这些暂存文件包含生成配置或恢复副本，不含密码。macOS 的 WindowServer 还可能自行更新布局及显示状态文件；本工具不直接编辑这些状态文件。

persist 通过显示 API 请求系统保存显示偏好，由 macOS 决定具体偏好文件和键；不写入上述用户恢复记录。

## 支持范围

- 二进制最低启动版本为 macOS 14.0；这不代表所有后续 macOS 版本均已实测。程序目前仅允许 Apple M1 Pro；已验证环境为 MacBook Pro M1 Pro、macOS 27.2，显示器包括 Dell P3424WE（3440×1440）及 Duo 两块 MB14FCD（各 1920×1200），均为 60 Hz。正式双屏整合版与专用程序实测的区别见验证记录。
- 通过系统原生显示管线连接的外屏。DisplayLink、Sidecar、虚拟屏不在支持范围，不能保证识别或修改成功。
- 其他 M1 Pro 外屏会按检测到的原生尺寸生成配置，但未逐款实测。系统或 GPU 渲染限制可能拒绝目标；工具应报错，不能承诺每台外屏都能启用原生尺寸 HiDPI。
- 软件重连与恢复要求 MacBook 内屏开启。
- 可保留多种型号的配置和恢复记录；它们共享一个全局显示开关基准。同厂商、同产品 ID 的覆盖影响该型号所有屏幕；安装和恢复按型号处理，模式切换按选中的屏幕处理。新旧记录基准冲突时停止自动操作，不修改其他型号的文件。
- 使用了 macOS 私有显示接口；其他系统版本未验证，系统升级可能改变接口或模式布局。工具找不到唯一模式时停止切换。
- 不改变显示线缆带宽、面板物理分辨率或刷新率上限；不承诺 HDR/VRR 或非整数刷新率组合。默认请求原生桌面尺寸的 HiDPI，按安装前刷新率就近取整选择模式。

## 命令行与源码

同文件夹内：

```sh
./MacHiDPI list
./MacHiDPI plan
./MacHiDPI status
./MacHiDPI enable
./MacHiDPI persist
./MacHiDPI install
./MacHiDPI reconnect
./MacHiDPI restore
```

有多台屏幕时，命令行可添加 `--display <当前显示器ID>`；ID 从 `list` 获取，重新连接后可能改变。`--yes` 跳过文字确认，仅供已明确授权的自动化；管理员授权仍由 macOS 处理。

`--all-resolutions` 的筛选范围和双屏处理范围见上文 Duo 一节。默认入口不带此参数，继续使用 11 档配置。

`export` 只向标准输出导出当前显示器生成的 plist，不安装。

源码为 `source/MacHiDPI.swift`。仓库内的构建和发布步骤以项目 `docs/DEVELOPMENT.md` 为准。

脱离仓库、单独使用此工具包时，可安装 Xcode Command Line Tools 后在包内编译：

```sh
swiftc -target arm64-apple-macos14.0 -warnings-as-errors source/MacHiDPI.swift -o MacHiDPI
```

单独编译会使原随包校验或构建记录失效。

实现与接口依据见项目 `docs/DEVELOPMENT.md`；实际通过范围以随包验证记录为准。
